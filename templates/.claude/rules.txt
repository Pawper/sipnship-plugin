# The rules every project gets with SipNShip, one block per rule, blocks
# split by a blank line. Owned by the plugin: the template sync refreshes
# it, so a project's own rules go in .claude/rules-own.txt (same format,
# ids starting "own-"), never here.
#
# sh scripts/rules.sh build makes, from this list and the project's own:
# the table of what enforces each rule in AGENTS.md (and CLAUDE.md), between
# its two marker lines. Never edit the table; change a block and rebuild.
# The rules step of the checks CI job fails a pull request whose table is
# stale.
#
# Keys, one per line:
#   id            the rule's name everywhere (the Rules tab, the switches)
#   kind          rule (the default) or watch: a watch refuses nothing,
#                 only reports, and has no switch
#   words         the rule in the builder's words
#   locked        yes: it turns only once the safety locks are released
#   applies-when  a file that must exist for the rule to apply; without it
#                 the rule is left out of the table
#   hook          the hook that refuses an agent inside a session
#   refusals      which of the hook's refusals, when one hook holds two rules
#   check         the script of the checks job's step that holds it
#   counterpart   PATH | REASON: the hook's row in the plugin's
#                 hooks/COUNTERPARTS.txt (PATH under the templates, or
#                 session-only, or repository-setting)
#   protects, catches, if-off   the builder's three plain lines
#   row           NAME | TEXT: one row of the table, as an agent reads it;
#                 a rule may have more than one

id: never-delete
words: Never delete; move aside
locked: yes
hook: block-delete
check: scripts/ci/delete-check.sh
counterpart: scripts/ci/delete-check.sh | the check fails a pull request that deletes a tracked file unless its body has a Deletes: line
protects: Work an agent might throw away.
catches: A delete, inside a session and on the pull request.
if-off: An agent can delete files, and a deleted file is gone unless someone finds it in history.
row: Never delete | The `block-delete` hook refuses rm, del, Remove-Item and git clean
row: Never delete, on the pull request | The `delete-check` step of the `checks` CI job fails a pull request that deletes a tracked file unless its body carries a line `Deletes: <reason>`

id: never-force-push
words: Never rewrite history on GitHub
locked: yes
hook: block-force-push
counterpart: repository-setting | a branch ruleset on all branches with Block force pushes and Restrict deletions, set by the owner (the bootstrap skill, section 3)
protects: The history your team shares.
catches: A forced push, inside a session. GitHub's own branch rules hold the rest.
if-off: An agent can rewrite a branch, and the commits it replaced can be lost for good.
row: Never force-push | The `block-force-push` hook refuses any forced push

id: tests-one-file
words: Tests run one file at a time
locked: no
hook: block-full-test-sweep
counterpart: .github/workflows/ci.yml | the full suite runs only on main, per-file on a pull request
protects: Your machines' time and your agents' focus.
catches: A full test run started from a session. The full suite runs on main.
if-off: An agent can start the whole suite, which takes a runner for minutes each time.
row: Tests per file | The `block-full-test-sweep` hook refuses a bare test command; CI runs the full suite on main

id: generated-pages
words: Generated pages are rebuilt, never edited
locked: no
hook: block-generated-page
check: status/check.sh
counterpart: .github/workflows/ci.yml | CI fails when a generated page is stale
protects: Pages that are built from other files.
catches: A direct edit of a generated page, and a page that is out of date.
if-off: A generated page can drift from the files it is built from, and the next rebuild erases a hand edit.
row: Nothing appended to a generated page | The `block-generated-page` hook refuses direct edits to the pages in `.claude/generated-pages.txt`; `sh status/check.sh` fails in CI when `STATUS.md` is stale

id: issue-has-state
words: Every issue has a state
locked: no
hook: require-state-label
counterpart: .github/workflows/state-label.yml | the workflow keeps every issue's State label in step with the board
protects: Your board.
catches: An issue filed without a state, and the nightly check for ones that slipped by.
if-off: Issues can land on the board with no state, and the board stops telling you what is ready.
row: Every issue has a State | The issue template requires it; the `require-state-label` hook refuses `gh issue create` without `--label state:...` and the REST form without `labels[]=state:...`; the `state-label` workflow keeps the label in step with the field; `sh scripts/state.sh` sets it on the board

id: ask-recommends-one
words: An ask with choices recommends one
locked: no
hook: require-state-label
refusals: an issue set to waiting on the owner whose ask gives choices and does not recommend exactly one
protects: Your time when an agent asks you to choose.
catches: An ask with choices and no recommendation, or more than one, set in front of you; the nightly check names any that slipped by.
if-off: An agent can hand you a list of choices with no word on which it would pick.
row: An ask recommends one | The `require-state-label` hook refuses setting an issue to waiting on the owner (`gh issue edit --add-label`, the REST labels call, `sh scripts/state.sh`) while the ask left on it in the last ten minutes gives choices and none, or more than one, ends with "Recommended.", or dresses a setup step as a choice between doing it and setting it aside (a setup step is a comment starting `Instructions:` with numbered steps, no choices); `scripts/ci/ask-lib.sh` reads the ask as the dashboard does, and the nightly `audit` names any that reached the owner another way

id: github-budget
words: The GitHub budget lasts the hour
locked: no
hook: require-gh-budget
counterpart: session-only | the hourly API budget is a live reading, not a property of a change
protects: The hour's GitHub allowance, shared by every agent.
catches: A GitHub call made when the budget is nearly spent.
if-off: Agents can spend the whole allowance, and every agent waits for the next hour.
row: The API budget lasts the hour | The `require-gh-budget` hook refuses a GraphQL `gh` command when fewer than 500 of the hour's points are left, naming the reset; the brief prints the budget; `scripts/issue-open.sh`, `pr-open.sh` and `pr-checks.sh` are REST

id: watch-red-main

words: A red main is seen
row: A red main is seen | The `full` CI job opens an issue labeled `ci-red` when it fails

id: agent-model
words: Each agent gets a model that fits its task
locked: no
hook: require-agent-model
counterpart: session-only | a dispatch happens inside a session, never on a pull request
protects: Your usage.
catches: An agent or workflow started without a model that fits.
if-off: Agents can start on the biggest model for small jobs, and your usage runs out sooner.
row: No usage wasted on dispatch | The `require-agent-model` hook refuses an agent or workflow dispatch without a model that fits the task

id: land-through-queue
words: Changes land only through the queue
locked: no
hook: require-batch-merge
counterpart: scripts/ci/merge-queue.sh | the queue is the only merge path and refuses what is not ready
protects: Main, from changes that were never tested together.
catches: A merge made by hand, and too many through the queue at once.
if-off: An agent can merge a change that was never tested with the others, and main can turn red.
row: Merging never outlasts the work | The `require-batch-merge` hook refuses a direct `gh pr merge` and more than two PRs through the queue without `--batch`, `--serial` or `--drain`; the queue refuses a change whose migration has not run; see `scripts/ci/QUEUE.md`

id: numbering
words: Numbers never collide
locked: no
check: scripts/ci/numbering-check.sh
protects: Files that must keep an order, such as migrations.
catches: Two files that share a number, and a task given a running number.
if-off: Two agents can take the same number, and the later one breaks the order.
row: Numbers never collide | The `numbering-check` step of the `checks` CI job fails when two numbered files share a number or a task file gains a running number; `scripts/next-number.sh` reserves the next free one

id: watch-runners
kind: watch
words: Runners never fail quietly
row: Runners never fail quietly | The nightly `audit` workflow, on the project's own runners, comments on the audit issue when a run sits queued for ten minutes, a runner is offline or fewer than two are online, or hosted runs are not starting; the session brief names a run queued over ten minutes at every session start; see `scripts/ci/RUNNERS.md`

id: clean-folder
words: A clean folder is part of done
locked: yes
hook: require-clean-worktree
counterpart: scripts/ci/merge-queue.sh | the queue refuses a pull request whose worktree is not clean
protects: Uncommitted work, which is lost when a folder is cleared.
catches: Finishing with files left over, in a session and at the queue.
if-off: An agent can finish with work uncommitted, and it is lost when the queue clears the folder.
row: A clean folder is part of done | The `require-clean-worktree` hook refuses to finish a task in a worktree with files outside `.scratch/`, stray images or build output, a process still running from it, or, at the session's end, any script this session started and left running; the merge queue refuses a pull request whose worktree is not clean

id: shared
words: Shared code changes alone
locked: no
check: scripts/ci/shared-check.sh
protects: Every agent's work, which leans on shared code.
catches: Shared code changed in the same pull request as other work.
if-off: A change to shared code can ride along with other work and break it for everyone.
row: Shared code changes alone | The `shared-check` step of the `checks` CI job fails a pull request that edits a path in `scripts/ci/shared-paths.txt` together with other work

id: small-files
words: Source files stay small
locked: no
check: scripts/ci/hotspots-check.sh
protects: Files two agents may need at once.
catches: A change that grows a source file past its size limit.
if-off: Files can grow until two agents keep colliding in them.
row: Source files stay small | The `hotspots` step of the `checks` CI job fails a pull request that grows a file past its limit in `scripts/ci/hotspots.txt` ("split before you add"), warns at 80% of the limit and when other open pull requests edit the same file; the session brief names the hotspots

id: quick-checks
words: Quick checks run before a push
locked: no
hook: require-local-checks
counterpart: .github/workflows/ci.yml | the checks job runs the same steps on the pull request
protects: Your runners' time.
catches: A push that would fail a cheap check on the pull request.
if-off: A cheap failure waits for the pull request to show it, and a runner spends minutes on it.
row: A cheap check fails before the push, not in CI | The `require-local-checks` hook runs `sh scripts/ci/checks-local.sh` on a `git push` from a branch that is not main, and refuses the push with the failures in the checks' own words; the script runs the steps of the `checks` CI job that call a project script, read from `ci.yml` so the two never drift, and takes the pull request body from `.scratch/body.md` or the open pull request; CI runs the same steps for an agent without hooks

id: work-has-ending
words: Work always has an ending
locked: yes
hook: block-loose-ends
refusals: a pull request closed without a comment; a detached worktree
counterpart: .github/workflows/audit.yml | the nightly audit reports branches left after their pull request ended
protects: Commits on a folder with no branch, which are lost with the folder.
catches: A pull request closed without a reason, and a detached folder.
if-off: An agent can leave work with no ending, and a commit made on a detached folder is lost.
row: Work always has an ending | The `block-loose-ends` hook refuses `gh pr close` without a comment and a detached worktree; `scripts/worktrees.sh` removes ended worktrees and their branches, keeping a closed branch's commits under a `closed/` tag; the nightly audit reports branches left on the remote after their pull request ended
